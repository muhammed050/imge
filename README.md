# النسخة المنشورة: IMGE

النسخة المستضافة تستخدم Cloudflare Worker وR2 لحفظ الصور كملفات دائمة **دون قاعدة بيانات**. ضغط WebP يتم في المتصفح (1920 بكسل، جودة 76، حد 2 MiB بعد الضغط). الصور تظهر لدى الزوار خلال 5 ثوانٍ؛ يتوقف التحديث عند إخفاء الصفحة لتقليل الاستهلاك. النسخة المحلية القديمة أدناه متاحة أيضًا عبر Docker.

- `npm run build`: ينتج Worker في `dist/server/index.js`.
- `.openai/hosting.json`: يربط تخزين R2 باسم `BUCKET`، ولا يستخدم D1.
- `worker/index.js`: الخادم المستضاف؛ `server.js`: الخادم المحلي ذو القرص الدائم.
- لا تحتاج مفاتيح تخزين في المتصفح.
- تحدد النسخة المستضافة 10 محاولات رفع لكل عنوان في الدقيقة عبر حجوزات R2 شرطية. تُحذف علامات التحديد القديمة عند وصول عمليات رفع لاحقة.
- حدود 500 صورة و512 MiB في النسخة المستضافة فحص قبل الرفع؛ قد تتجاوز قليلًا عند طلبات متزامنة. لا تُحذف الصور تلقائيًا. إعدادات `.env` العددية أدناه تخص نسخة Docker.
- تحقق الخادم المستضاف من التوقيع والحجم؛ ضغط الصورة وإزالة بياناتها يحصلان في المتصفح. لا يوجد فحص محتوى آلي أو إعادة ترميز ثانية في الخادم المستضاف.
- `ADMIN_TOKEN` اختياري في إعدادات الاستضافة للحذف الإداري؛ لا يُضمّن في الكود.

# IMGE — حائط صور مباشر

أي زائر يرفع صورة، فتظهر للجميع مباشرة وتتقاسم الصور مساحة الحائط بالتساوي. صورة واحدة تملأ الحائط؛ صورتان نصفان؛ ثلاث صور ثلاث مساحات متساوية، وهكذا. يدعم الهاتف والعربية، السحب والإفلات، معاينة الصورة، تكبيرها وملء الشاشة.

## التخزين والتكلفة

**بدون قاعدة بيانات وبدون مفاتيح خدمات خارجية.** الصور ملفات WebP على قرص دائم. فهرس الصور يُقرأ من أسماء الملفات عند التشغيل. الواجهة تتحقق من الإضافات كل خمس ثوانٍ. يحتفظ الخادم المحلي أيضًا بمسار Server-Sent Events للعملاء المخصصين.

- ضغط على الخادم باستخدام sharp إلى حد أقصى 1920×1920، بجودة 76؛ حذف بيانات EXIF والموقع أثناء التحويل.
- حد الرفع 8 MiB و24 مليون بكسل؛ الصور المتحركة تُحفظ كإطار ثابت.
- حد افتراضي 500 صورة و512 MiB؛ عند امتلائه يُرفض الرفع دون حذف الصور السابقة.
- ثلاث عمليات معالجة متزامنة و10 محاولات رفع في الدقيقة لكل عنوان اتصال.
- لا تسجيل دخول، ولا حفظ للصور في localStorage، ولا صور تجريبية منشورة على الحائط.

لا توجد رسوم لقاعدة بيانات أو مزوّد صور. **الاستضافة والقرص والمرور الشبكي قد تكون مدفوعة**؛ السعر يعتمد على مزوّدك. هذا حل اقتصادي خصوصًا إن كان لديك خادم. لا يعني تخزين الملفات أن الصور مؤقتة.

## التشغيل

يتطلب Node.js 22 أو أحدث.

```sh
npm ci
cp .env.example .env
npm start
```

افتح `http://localhost:3000`. للاختبارات: `npm test`.

## النشر مع تخزين دائم

على VPS أو استضافة Docker تدعم القرص الدائم:

```sh
docker compose up -d --build
```

اربط نطاقك عبر reverse proxy مع HTTPS على المنفذ 3000. في nginx عطّل `proxy_buffering` لمسار `/api/events` واضبط `proxy_read_timeout 60s` و`client_max_body_size 8m`. نبضات SSE تُرسل كل 20 ثانية.

**غير مناسب للنشر على Vercel أو قرص مؤقت:** الصور ستضيع بعد إعادة التشغيل أو النشر. عند استعمال منصة حاويات اربط persistent volume بالمسار `/app/data`. الملف `compose.yaml` يعرّف named volume، يبقى بعد إعادة إنشاء الحاوية. لا تستخدم `docker compose down -v` إلا إذا أردت حذف الصور عمدًا. انسخ volume احتياطيًا.

شغّل **نسخة واحدة** من الخادم؛ الفهرس والمزامنة في الذاكرة. التوسع لعدة نسخ يتطلب تخزينًا ومزامنة مشتركة. محدد الرفع يستخدم عنوان الاتصال الفعلي ولا يثق في X-Forwarded-For؛ خلف proxy قد يتشارك الزوار الحد نفسه. اضبط تحديد معدل الطلبات على proxy موثوق عند التوسع، ولا تثق بعناوين يرسلها العميل دون ضبط.

## الإعدادات

| المتغير | الافتراضي | الوظيفة |
|---|---|---|
| `PORT` | `3000` | منفذ الموقع |
| `DATA_DIR` | `./data` | مسار قرص الصور الدائم |
| `MAX_PHOTOS` | `500` | أقصى عدد صور |
| `STORAGE_LIMIT_MB` | `512` | حصة الصور بالميبيبايت |
| `ADMIN_TOKEN` | فارغ | سر إدارة اختياري لحذف الصور |

## إزالة المحتوى

الموقع عام والرفع فوري؛ لا توجد مراجعة محتوى تلقائية. عيّن `ADMIN_TOKEN` طويلًا وعشوائيًا على الخادم (لا تضعه في المتصفح أو GitHub). لحذف صورة مسيئة:

```sh
curl -X DELETE 'https://YOUR-DOMAIN/api/photos/PHOTO_ID.webp' \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

قائمة المعرفات: `GET /api/photos`. الحذف يزيل الملف ويحدث حائط جميع الزوار. التخزين المؤقت للصور مدته يوم؛ قد تبقى النسخ المحفوظة سابقًا عند الزائر إلى انتهاء التخزين المؤقت. هذا الإصدار مناسب كبداية صغيرة؛ خدمة عامة واسعة تحتاج مراقبة إساءة الاستخدام وحماية إضافية عند الحافة.

## التحقق

الاختبارات تشمل توزيع المساحات وعدم تداخلها، رفع صورة حقيقية وتحويلها، وصول التحديث للزوار، الملفات التالفة والأنواع المرفوضة، الحصة عند الرفع المتزامن، رفض الحذف غير المصرح، وبقاء الصور بعد إعادة التشغيل.
